Purpose

Search algorithms differ in the way they explore the state space. This table summarizes their search strategies, completeness, optimality, and typical resource requirements. Actual execution results depend on the puzzle configuration, successor ordering, and implementation.

Theoretical Comparison of Search Algorithms

Algorithm Search Strategy Heuristic Complete Optimal Memory Usage
Breadth-First Search Shallowest state first None Yes Yes* High
Depth-First Search Deepest state first None Conditional No Low
Iterative Deepening DFS (IDDLS) Repeated depth-limited DFS None Yes Yes* Low
Depth-Limited Search DFS up to a depth limit None Conditional No Low
Greedy Best-First Search Lowest h(n) Misplaced / Manhattan Yes* No Potentially high
A* Search Lowest g(n) + h(n) Misplaced / Manhattan Yes* Yes* High

*BFS is optimal for equal step costs. UCS and A* have standard cost and heuristic assumptions. DFS and DLS completeness depends on the search space and depth limit. GBFS is complete on a finite graph when duplicate states are handled correctly, but it is not generally optimal. Memory labels are qualitative rather than measured values.

Performance Metrics to Compare

For a fair experimental comparison, run every algorithm on the same initial and goal states and record these metrics:

  • Whether a solution was found
  • Number of moves in the returned solution
  • Nodes generated and nodes expanded
  • Maximum search depth
  • Execution time
  • Approximate memory usage

These measurements should be populated by actual algorithm implementations. This page currently presents theoretical differences and does not claim to have run all six algorithms.
