Introduction

Search algorithms explore possible puzzle states to find a path from an initial configuration to a goal configuration. Their performance differs in terms of search strategy, memory usage, completeness and solution optimality.

1. Breadth-First Search (BFS)

Principle: Explores states level by level, expanding the shallowest unvisited state first.

Working

  1. Insert the initial state into a FIFO queue.
  2. Remove the front state and test whether it is the goal.
  3. Add its unvisited successors to the queue.
  4. Repeat until the goal is found or the queue is empty.

Advantages

  • Complete for a finite branching factor.
  • Finds a shortest path when all moves have equal cost.

Limitations

  • Can consume substantial memory.
  • Explores many states that may not lead directly to the goal.

Completeness: Yes, under standard finite-branching assumptions.

Optimality: Yes, for equal step costs.

Time / Space: O(bd) / O(bd).

2. Depth-First Search (DFS)

Principle: Explores one path deeply before backtracking.

Working

  1. Place the initial state on a stack.
  2. Pop a state and check whether it is the goal.
  3. Push unvisited successors onto the stack.
  4. Continue until the goal is found or the stack is empty.

Advantages

  • Usually uses less memory than BFS.
  • May find a solution quickly if it explores a suitable path.

Limitations

  • May explore a long, unproductive path.
  • Does not guarantee the shortest solution.

Completeness: Not generally guaranteed in infinite-depth spaces; yes in finite graphs with cycle detection.

Optimality: No.

Time: O(bm). Space: O(bm) for standard tree-search DFS.

3. Iterative Deepening Depth-First Search (IDDLS)

Working Principle

Iterative Deepening Depth-First Search combines the space efficiency of Depth-First Search with the completeness of Breadth-First Search. It repeatedly performs Depth-Limited Search, increasing the depth limit by one in each iteration until the goal state is found.

How It Works

  1. Start with a depth limit of 0.
  2. Perform Depth-Limited Search from the initial state.
  3. If the goal is not found, increase the depth limit by 1.
  4. Repeat the search until the goal is found or the search is terminated.

Advantages

  • Complete when the branching factor is finite.
  • Optimal when all actions have equal cost.
  • Uses less memory than Breadth-First Search.

Limitations

  • Repeats the exploration of shallow states in each iteration.
  • May perform more work than BFS when the solution depth is small.

Complexity

Time Complexity: O(bd)

Space Complexity: O(bd)

Complete: Yes, for a finite branching factor.

Optimal: Yes, when all actions have equal cost.

4. Depth-Limited Search (DLS)

Principle: DFS with a maximum search depth limit.

Working

  1. Start from the initial state.
  2. Expand successors while the current depth is below the limit.
  3. Backtrack when the limit is reached without finding the goal.

Advantages

  • Prevents search from continuing indefinitely down a path.
  • Uses relatively little memory.

Limitations

  • Fails to find solutions deeper than the selected limit.
  • A poor limit may waste effort or miss a solution.

Completeness: Only when the limit reaches a solution depth and relevant branches are explored.

Optimality: No, in general.

Time / Space: O(bl) / O(bl), where l is the depth limit.

5. Greedy Best-First Search (GBFS)

Principle: Expands the state that appears closest to the goal using the heuristic h(n).

Working

  1. Insert the initial state into a priority queue.
  2. Prioritize states with the lowest heuristic value.
  3. Expand the best-ranked state and insert its unvisited successors.
  4. Repeat until the goal is found or the frontier is empty.

Heuristics

  • Misplaced Tiles: Counts numbered tiles outside their goal positions.
  • Manhattan Distance: Sums each numbered tile's horizontal and vertical distance from its goal position.

Advantages

  • Heuristics can guide the search toward promising states.
  • May explore fewer states than uninformed methods on some puzzles.

Limitations

  • May return a non-shortest solution.
  • A heuristic can be misleading and does not account for accumulated path cost.

Completeness: Yes on a finite graph with duplicate detection and a correctly implemented search.

Optimality: No, in general.

Priority: f(n) = h(n), with g(n) tracked separately as path depth/cost.

Time / Space: O(bm) in the worst case.

6. A* Search

Principle: Expands the state with the smallest estimated total solution cost.

Working

  1. Start with the initial state and g(n) = 0.
  2. Calculate f(n) = g(n) + h(n).
  3. Expand the state with the lowest f(n).
  4. Update successor path costs and priorities when a better path is found.

Advantages

  • Can find optimal solutions with a suitable admissible heuristic and correct implementation.
  • Uses both path cost and estimated remaining cost.

Limitations

  • Can require large amounts of memory.
  • Performance depends on the quality of the heuristic.

Completeness: Yes under standard positive-cost and finite-branching assumptions.

Optimality: Yes with an admissible heuristic in tree search; graph search needs suitable consistency or reopening behavior.

Priority: f(n) = g(n) + h(n).

Time / Space: Exponential in the worst case.
